# ADR-011 実際の状態と判定を別の言葉にし、要メンテ車両はきっかけを問わない

## 背景

「重度パンク」「要メンテ」「貸出除外」は、資料体系一覧で早めに定義を決めるとしていた用語である。これまでの資料では、次のような揺れがあった。

- 「重度パンクと判定」という書き方が、タイヤが実際に重度パンクであることなのか、システムがそう判定しただけ（誤検知を含む）なのか区別できない。
- 「要メンテ車両」は、資料07 では申告された車両も含めて使い、企画書ではシステムが判定した車両の意味で使っていた。
- 予約・貸出の対象から外すことを、資料体系一覧は「貸出除外」、旧仕様書 第35章は「貸出停止」、資料07 は「貸出を止める」と書いていた。

## 決めたこと

1. タイヤの実際の状態（正常・軽度・中度・重度パンク）と、システムの判定の結果（異常判定・正常判定）を別の言葉にする。
2. 重度パンクは、意味を状態（空気がほぼ抜け、段差でリムに強い衝撃が来る状態）で書き、実験・評価のラベルは空気圧（旧仕様書の目安 0〜50 kPa、【仮】）で付ける。
3. 要メンテ車両は、きっかけを問わず「点検・修理が必要だとして貸出除外した車両」とする。きっかけは「要メンテの理由」として持つ。MVP で作るのは異常判定がきっかけのものだけ。
4. 予約・貸出の対象から外すことは「貸出除外」にそろえ、「貸出停止」は使わない。

## 検討した案

| 論点 | 案 | 良い点 | 弱い点 |
|---|---|---|---|
| 実際の状態と判定 | 分ける（採用） | 検知率・誤検知率を「実際の状態 × 判定」でそのまま定義できる。誤検知を含むことが言葉からわかる | 「異常判定」という言葉を覚える必要がある |
| | 分けない | 短く書ける | 誤検知と実際の重度パンクの区別があいまいになる |
| 重度パンクの決め方 | 意味は状態、ラベルは空気圧（採用） | 現場に伝わる意味と、測れる基準を両方持てる | 2つの書き方がずれないよう気をつける必要がある |
| | 空気圧の範囲だけ | 測れて、実験のラベルと一致する | 数字だけでは、なぜその範囲なのかが伝わらない |
| | 状態だけ | 現場の感覚に近い | 実験のラベルが人によってぶれる |
| 要メンテ車両の範囲 | きっかけを問わない（採用） | 資料07（今の業務）と To-Be で同じ言葉を使える。申告の連携を将来足しても言葉を変えなくてよい | MVP で作らないきっかけも定義に入る |
| | 異常判定した車両だけ | MVP で作る範囲と一致する | 資料07 の使い方と食い違う |
| | 要点検と要メンテに分ける | 誤検知との区別がはっきりする | 状態が増え、MVP で作るものが増える |
| 外すことの呼び方 | 貸出除外（採用） | 資料体系一覧・資料14 の流れと同じ | ふつうの言い方ではない |
| | 貸出停止 | ふつうの言い方 | 資料体系一覧を直す必要がある |
| | 使い分ける（除外＝自動、停止＝手動） | 自動と手動を区別できる | MVP に手動で止める機能がなく、今は片方しか使わない |

## 決めた理由

- いちばん取り違えやすいのは「システムが異常判定した」と「実際に重度パンクだった」の違いで、PoC の評価（検知率・誤検知率）も、要メンテ車両の解除（誤検知だった場合）も、この区別の上に成り立つため。
- 要メンテ車両を広く定義しても、MVP で作る範囲は「要メンテの理由」で絞れるため。

## 影響・注意点

- 企画書（資料01）の「重度パンクと判定」「貸出から外す」を、「異常判定」「貸出除外」に直した（0.4）。
- これから書く資料・Issue・会話では、用語集（資料02）の定義どおりに書く。
- ラベルの空気圧の境目と、範囲のすき間の扱いは T15（資料09）で決める（資料04 K-015）。
- 車両の状態の名前（要メンテ、点検中 など）は T25・T36 で決める。
