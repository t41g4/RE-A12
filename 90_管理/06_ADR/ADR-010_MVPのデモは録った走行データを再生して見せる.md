# ADR-010 MVP のデモは録った走行データを再生して見せる

## 背景

MVP のデモ（12/9）では、重度パンクを検知してから貸出から外し、点検して戻すまでを見せる。重度パンクの状態で実際に走ると、リムやタイヤが傷む。会場で自転車を走らせられるか、天候はどうかという問題もある。

## 決めたこと

- MVP のデモで「重度パンクを検知する」場面は、**実験で録った走行データをデバイスの判定に流し込んで（再生して）** 見せる。判定から先（送信・要メンテ車両への切り替え・デモアプリ・管理Web・解除）は実機で動かす。
- 正常な走行で外されないことも、正常な走行データを再生して確かめる。
- MVP の成功基準は、資料01 7.2 の M1〜M3 を、それぞれ3回続けて成功することとする。

## 検討した案

| 案 | 良い点 | 弱い点 |
|---|---|---|
| 実車で通しで走る | 「本当に走って検知した」ことを見せられ、説得力がいちばん高い | 走る場所・安全・天候に左右される。重度パンクで走るたびにリムやタイヤが傷む |
| 録ったデータを再生する（採用） | 会場を選ばず、同じ条件で何度でも繰り返せる | 「本当に走って検知した」ことは見せられない。再生の仕組みを作る必要がある |
| 両方（実車での検知は事前に録画し、当日は再生） | 説得力と確実さの両方を取れる | 準備の手間がいちばんかかる |

## 決めた理由

- 期限（12/9）までに、確実に繰り返せるデモにするため。
- 検知の性能は PoC で測るため、MVP では検知したあとの仕組みが通しで動くことを確かめれば足りるため。

## 影響・注意点

- デバイスに、録ったデータを判定に流し込む仕組み（再生）が要る。デバイスの設計（T35）と実装（T41）に入れ、機能一覧（T26）にも載せる。
- 再生で動くことは、実際の走行で動くことの証明にはならない。センサーから読み取った値で判定まで動くことは、実車試験（T47）で確かめる。
- 成果報告（T52）では、再生で見せていることを断る。
