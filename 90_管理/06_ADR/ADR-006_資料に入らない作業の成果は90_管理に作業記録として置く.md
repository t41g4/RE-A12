# ADR-006 資料に入らない作業の成果は 90_管理 に作業記録として置く

更新日：2026-11-27
前提資料：なし

| 項目 | 内容 |
|---|---|
| 状態 | 決定 |
| 決めた日 | 2026-11-27 |
| 関係する作業・資料 | T02（#3）、資料06（#64） |

## 背景

T02「既存の仕様書・データ・機材を棚卸しする」の成果（使う／作り直す／使わない の一覧）は、資料体系一覧の37件のどの資料にも入らなかった。ほかの作業でも、資料にならない成果（調査のまとめ、確認の記録など）が出ることが見込まれる。置き場所を決めておかないと、作業ごとに置き方がばらつく。

## 決めたこと

- 作業（ラベル「区分:作業」）の成果は、資料体系一覧の資料に書けるものはその資料に書く（例：T01 の体制・役割 → 資料01 企画書 8章）。
- どの資料にも入らない成果だけを、**作業記録**として `90_管理/T番号_内容.md` に置く（例：`90_管理/T02_既存資産の棚卸し.md`）。
- 作業記録には資料番号を付けず、資料体系一覧の37件にも含めない。
- 作業記録の最初に、作業（T番号と Issue 番号）・更新日・前提を書く。

## 検討した案

| 案 | 良い点 | 弱い点 |
|---|---|---|
| `90_管理/T番号_内容.md` に作業記録として置く（採用） | 資料の数が増えない。ファイルなので、あとの資料から参照・リンクしやすい | 資料体系一覧に載らないので、置き方の決まりを別に知っておく必要がある |
| Issue のコメントに書く | ファイルも資料も増えない | あとから探しにくい。ほかの資料からリンクしにくく、プルリクエストでの確認も通らない |
| 資料体系一覧に番号付きの資料として足す | 一覧ですべてを見渡せる | 一覧と Issue の追加が要る。作業のたびに資料が増え、資料の番号と作成順の対応が崩れる |
| 専用のフォルダ（例：`91_作業記録/`）を作る | 資料と作業記録がはっきり分かれる | フォルダ構成を変える必要がある。いまは件数が少ないので効果が小さい |

## 決めた理由

- あとの資料（資料08・09・22 など）から参照しやすく、プルリクエストで確認も通せるため。
- 資料体系一覧の番号と作成順の対応を崩さずに済むため。

## 影響・注意点

- 置き方の決まりがわかるよう、資料体系一覧の「方針」と README のフォルダ構成に1行ずつ足した。
- 作業記録が増えて 90_管理 が見にくくなったら、専用フォルダへ移すことを見直す。
