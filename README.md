# RE-A12：シェアサイクル企業向け「要メンテ車両」自動検知システム

シェアサイクル車両の「重度パンク」を振動から自動検知し、返却時にクラウドへ通知して、貸出対象から自動で外すシステム。研究・PoC・MVP フェーズ。

## 進め方

作業と資料を [Issue](https://github.com/t41g4/RE-A12/issues) で1件ずつ進める。

| 管理するもの | 場所 | 中身 |
|---|---|---|
| 作業の順番・完了の条件・進み具合 | Issue（ラベル「区分:作業」、タイトル「T01〜T57」） | 企画からMVP・運用までの57作業 |
| 資料の進み具合 | Issue（ラベル「区分:資料」、タイトル「資料01〜資料37」） | 作る資料37件 |
| 資料の構成・中身・保存先 | `00_全体/00_資料体系一覧.md` | 資料37件の一覧とフォルダ構成 |

- フェーズは [Milestone](https://github.com/t41g4/RE-A12/milestones)（1 企画〜6 導入・運用）。フェーズをまたぐものはラベル「横断」で、Milestone はない。
- ラベル「種別:関門」は、完了の条件を満たすまで次のフェーズに進まない判断の節目。
- 各 Issue の本文に、完了の条件・前提・関係する資料や作業をリンクで書いてある。
- ステータスはプロジェクトボード「RE-A12」で管理する。順番は Todo → In Progress → 確認中 → Done で、止まっているものは保留。
  - Todo・In Progress・Done は Issue の状態と連動しているので、英語の名前のまま使う。Done に動かすと Issue も自動で閉じ、Issue を閉じると Done になる。
  - 期限はボードの「期限」項目に入れる。

## フォルダ構成

| フォルダ・ファイル | 中身 |
|---|---|
| `CLAUDE.md` | Claude への進め方の指示（Claude Code はこのファイルを自動で読む） |
| `00_全体/` | 企画・PoC・要件定義・全体設計・テスト計画/結果・運用 |
| `10_データ・検知/` | データ収集計画、データセット仕様、検知アルゴリズム仕様 |
| `20_デバイス/` | 部品選定、安全性評価、デバイスの設計書・設置手順 |
| `30_クラウド・API/` | クラウドの設計書、テーブル定義 |
| `40_管理Web/` | 画面設計、権限設計、管理Webの設計書・マニュアル |
| `90_管理/` | 用語集、計画書、課題・リスク表、議事録、ADR、品質計画、リリース計画、作業記録（資料に入らない作業の成果、`T番号_内容.md`。ADR-006） |

まだ資料のないフォルダは、最初の資料ができたときに作る。

旧プロジェクトの仕様書（PROJECT_SPEC 第5版）はリポジトリに入れず、claude.ai のプロジェクトに置いている。資料を作るときに内容を抽出し、見直す元として使う。Issue の「旧仕様書の参考箇所」はこの仕様書の章を指す。
